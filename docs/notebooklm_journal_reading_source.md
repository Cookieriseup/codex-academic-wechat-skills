# NotebookLM Source: 期刊阅读与公众号转化规范

本文件用于上传到 NotebookLM，作为阅读学术期刊文章、生成中文阅读笔记、组会汇报材料和微信公众号草稿的固定规范。

使用方式：把本文件与论文 PDF、DOI 页面、网页链接、摘要文本、已有笔记或优秀范例一起上传到同一个 NotebookLM notebook。之后在 NotebookLM 中要求它“严格按照本文件的规范”输出。

## 一、任务目标

请将选定学术期刊文章转化为：

1. 中文 Markdown 阅读笔记；
2. HTML 阅读报告或公众号预览稿；
3. 适合转成 Word 的结构化报告；
4. 组会汇报提纲；
5. 微信公众号分享草稿；
6. 多篇论文横向对比或期刊新文速览。

适用领域包括：管理学、心理学、AI、经济学、图书情报管理、知识产权管理、创新创业、技术转移、平台治理、数据治理与科技政策。

## 二、输入材料类型

可以处理以下材料：

1. 论文 PDF；
2. DOI 或网页链接；
3. 论文截图；
4. 摘要文本；
5. 已有阅读笔记；
6. 一组论文或一期期刊目录；
7. 高质量公众号范例。

如果只提供摘要或网页简介，必须在输出中说明“证据边界”：只能基于摘要/网页信息，不能假装已经阅读全文。

## 三、原文摘录与剖析规则

所有阅读报告、公众号草稿、组会材料、非期刊报告解读和多篇论文速览，都必须包含“原文摘录与剖析”。

1. 单篇论文、单篇报告、单篇文章或其他单一材料：至少引用 5 小段原文。
2. 多篇论文、期刊新文速览或多材料对比：每一篇/每一份材料至少引用 2 小段原文。
3. 所选原文必须能体现文章的精彩之处、点睛之笔、关键概念、方法转折、核心发现或边界条件，不能只是因为出现了关键词。
4. 每段原文后必须跟随中文剖析，说明这段话为什么关键、如何支撑作者观点、方法设计、发现或局限。
5. 原文引用应保持短小，不要连续大段搬运；如果只能看到标题、目录或摘要，必须标注“无法满足原文引用数量”，并说明证据边界。

## 四、固定阅读流程

阅读论文时必须按以下顺序：

1. 先看标题、作者、期刊、年份、摘要、关键词和 DOI；
2. 再看 introduction，识别研究问题和研究动机；
3. 再看 theory/hypotheses 或 conceptual framework，识别核心概念和理论逻辑；
4. 再看 method/data，识别研究设计、样本、数据来源、变量、模型或实验流程；
5. 再看 results/tables/figures，解释主要结果、统计指标和图表含义；
6. 最后看 discussion/conclusion，提炼贡献、局限、边界条件和未来研究方向。

必须区分：

1. 论文作者明确提出的观点；
2. 数据或结果实际支持的结论；
3. 阅读者基于论文做出的延伸解释；
4. 不能由论文推出的过度解读。

## 五、必须提取的信息

每篇论文至少提取：

| 字段 | 要求 |
|---|---|
| Title | 保留英文题名 |
| 中文题名 | 准确、自然，不要机械翻译 |
| Authors | 作者信息，无法识别则标记“待人工核验” |
| Year | 年份，无法识别则标记“待人工核验” |
| Journal/Source | 期刊或来源 |
| DOI/URL | DOI 或网页链接 |
| Article type | 实证、理论、综述、方法、案例等 |
| Research question | 研究问题 |
| Research design | 研究设计 |
| Data/Sample | 数据和样本 |
| Method | 方法、模型、实验或识别策略 |
| Key findings | 核心发现 |
| Original excerpts | 单篇至少5小段原文；多篇每篇至少2小段原文，并逐段剖析 |
| Contributions | 理论、方法、实践贡献 |
| Limitations | 局限和不可误读之处 |
| Transferable insights | 对创新创业、技术转移、知识产权管理、AI治理、平台治理等领域的启发 |

不要编造作者、年份、期刊、DOI、样本、统计结果或结论。

## 六、术语规则

专业术语第一次出现时采用：

英文术语（中文解释）

例如：

- moderation（调节效应）
- mediation（中介效应）
- endogeneity（内生性）
- robustness check（稳健性检验）
- fsQCA（模糊集定性比较分析）
- Algorithmic Facial Expression Analysis, AFEA（算法面部表情分析）
- Facial Action Coding System, FACS（面部动作编码系统）
- action units, AU（面部动作单元）
- CRO（合同研究组织）
- CDMO（合同研发生产组织）

重要术语应保留英文，不要完全中文化。

## 七、统计和方法解释规则

不能只写“使用回归模型”“结果显著”。必须解释：

1. 这个方法用来回答什么问题；
2. 样本是什么；
3. 关键变量是什么；
4. 结果方向是什么；
5. 效应大小或强弱如何理解；
6. 统计显著性意味着什么，不意味着什么；
7. 是否有稳健性检验、异质性分析、机制检验或边界条件；
8. 该方法是否能支持因果判断。

如果论文使用图表，必须解释：

1. 图表展示了什么；
2. 图表支持了哪一条结论；
3. 图表不能证明什么；
4. 读者最容易误读哪里。

## 十、微信公众号草稿规则

公众号稿可以有传播感，但不能夸大论文结论。

推荐结构：

1. 标题：有吸引力，但必须忠于论文；
2. 导语：100-200字，提出真实问题或反直觉发现；
3. 这篇论文研究了什么；
4. 它为什么重要；
5. 作者怎么研究；
6. 最关键的发现；
7. 方法或统计指标的通俗解释；
8. 别误读：说明局限、边界和不能推出的结论；
9. 可以迁移到哪里：创新创业、技术转移、知识产权管理、AI治理、平台治理等；
10. 结尾：一个清晰 takeaway 或讨论问题。

写作风格：

1. 中文自然，不要翻译腔；
2. 段落短，适合手机阅读；
3. 可以使用具体场景开头；
4. 不要只复述摘要；
5. 不要把所有结果都写成“显著促进”；
6. 不要把相关关系写成因果关系；
7. 不要忽略样本、方法和边界条件；
8. 对读者解释“这件事为什么值得关心”。

## 十一、HTML 输出规则

如果用户要求输出 HTML，请生成完整、可复制保存为 `.html` 的单文件 HTML。HTML 应当适合浏览器预览、公众号排版工具二次处理或复制到富文本编辑器。

HTML 输出要求：

1. 使用完整结构：`<!doctype html>`、`html`、`head`、`meta charset="utf-8"`、`title`、`style`、`body`。
2. CSS 写在 `<style>` 中，不依赖外部资源。
3. 页面宽度适合手机阅读，正文容器建议 `max-width: 760px`。
4. 使用清晰层级：`h1`、`h2`、`h3`、`p`、`table`、`blockquote`、`figure`、`figcaption`。
5. 图表说明可以先用占位模块表示，例如：

```html
<figure class="chart-placeholder">
  <div class="chart-box">图表占位：请在此插入 Figure 1 或结果表</div>
  <figcaption>图注：说明该图表展示什么、支持什么结论、不能证明什么。</figcaption>
</figure>
```

6. 如果论文中有真实图表，但当前无法提取图片，请不要编造图片；使用图表占位和说明。
7. 表格要使用 HTML table，不要只用纯文本对齐。
8. 适合公众号的 HTML 应避免复杂 JavaScript，不要使用交互脚本。
9. 所有引用、DOI、证据边界和待核验项必须保留。
10. HTML 文字风格仍需符合本规范：自然中文、保留关键英文术语、解释统计和方法、避免夸大。

## 十二、组会汇报规则

组会汇报要更学术、更克制，重点讲清楚：

1. 研究问题；
2. 文献缺口；
3. 理论框架；
4. 研究设计；
5. 方法与变量；
6. 主要结果；
7. 贡献；
8. 局限；
9. 可借鉴之处；
10. 可讨论问题。

输出时可以给出 8-12 页 PPT 式提纲：

| 页码 | 标题 | 内容要点 |
|---|---|---|
| 1 | 论文基本信息 | 题名、作者、期刊、研究问题 |
| 2 | 研究背景 | 为什么重要 |
| 3 | 文献缺口 | 前人没解决什么 |
| 4 | 理论逻辑 | 核心机制 |
| 5 | 数据与方法 | 样本、变量、模型 |
| 6 | 主要结果 | 关键发现 |
| 7 | 稳健性/机制 | 可信度 |
| 8 | 贡献与局限 | 如何评价 |
| 9 | 迁移启发 | 对本人研究的价值 |
| 10 | 讨论问题 | 可供组会讨论 |

## 十三、反面要求

不要出现以下问题：

1. 太泛泛，只说“本文具有重要理论和实践意义”；
2. 翻译腔太重；
3. 只复述摘要；
4. 不区分作者结论和自己的推测；
5. 不解释统计指标；
6. 不说明样本和方法；
7. 把相关关系写成因果关系；
8. 只写优点，不写局限；
9. 公众号标题夸张到偏离论文；
10. 编造作者、年份、期刊、DOI或结果。

## 十五、音频概览提示词

NotebookLM Audio Overview 当前主要支持选择格式、语言、长度和输入自定义 prompt。可以在 prompt 中要求语速、语调、主持人风格、开头问候和结构，但具体音色不一定能被严格控制；播放速度通常可以在播放器中调整。不要要求 NotebookLM 使用某个真实人物声音或克隆个人声音。

如果要生成 NotebookLM Audio Overview，可使用以下 prompt：

请生成中文音频概览，风格像面向管理学、创新创业和技术转移研究生的学术播客。请不要泛泛介绍论文，而是重点解释：研究问题是什么，作者为什么研究它，使用了什么方法和数据，最关键发现是什么，哪些结论不能过度解读，以及这篇论文对创新创业、技术转移、知识产权管理或AI治理有什么启发。请保留关键英文术语并用中文解释，语气清晰、有层次、适合通勤时收听。

### 音频配置提示词模板

请生成中文 Audio Overview，并尽量遵守以下播客配置：

- 语言：简体中文。
- 格式：Deep Dive，两位主持人对谈。
- 听众：管理学、创新创业、技术转移、知识产权管理方向的研究生和青年教师。
- 时长：约 8-12 分钟。如果系统无法精确控制时长，请优先保证结构完整。
- 语速：中等偏慢，适合通勤收听；遇到英文术语、统计方法和核心结论时稍微放慢。
- 语调：清晰、克制、有学术播客感，不要夸张营销腔。
- 音色：尽量使用温和、专业、清楚的主持人声音；一位负责提问和转场，一位负责解释论文内容。不要模仿任何真实人物声音。
- 开头固定问候：大家好，欢迎收听本期“期刊阅读笔记”。今天我们一起读一篇关于【论文主题】的研究。
- 开头介绍顺序：先说论文题名、期刊、作者和研究问题，再说明这篇论文为什么值得听。
- 结构：研究问题 -> 理论背景 -> 数据与方法 -> 核心发现 -> 不能误读的地方 -> 对创新创业/技术转移/知识产权管理的启发 -> 结尾总结。
- 术语处理：保留关键英文术语，并用一句中文解释。例如 moderation、mediation、robustness check、fsQCA、endogeneity。
- 统计解释：不要只说“显著”，要解释方向、含义、样本和边界。
- 风格限制：不要编造论文没有的结论，不要把相关关系说成因果关系，不要使用夸张标题党语气。
- 结尾固定话术：以上就是本期音频概览。真正写作或汇报前，建议回到原文核对模型、图表和边界条件。

请根据上传的论文和本规范生成音频概览。
